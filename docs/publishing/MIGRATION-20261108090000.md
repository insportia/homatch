**Status: NOT APPLIED. It runs only on the owner's explicit authorization.** Merging PR #226
does not apply it. `deploy.yml`'s publishing step (`scripts/publishing/apply-migration.mjs`) is

answers `PUBLISHING_WORKER_NOT_CONFIGURED` until its own token is set.

## What it changes (audited 2026-10-16 against production)

- **The only DROP**: `publishing_engine_jobs_status_check`, recreated in the same transaction
  with the 8 v1 statuses plus `QUEUED, PUBLISHING, ADMIN_ACTION_REQUIRED, AUTH_REQUIRED,
  REJECTED, FAILED`.
- **Additive**:
  - jobs columns `channel` (default `OWNER_HANDOFF`), `contact_consent_at`, `status_reason`,
    `admin_claimed_by`, `admin_claimed_at`;
  - tables `publishing_accounts`, `publishing_account_audit`, `publishing_account_sessions`,
    `publishing_operations`, `publishing_artifacts` (all RLS on, service-role only);
  - functions `publishing_account_write`, `publishing_op_*` (5), `publishing_artifacts_due`
    and `_forget`;
  - private bucket `publishing-artifacts`.
- **`create or replace`, same signature and grants**: `publishing_publication_write` and
  `publishing_listing_lifecycle`.
- **Not touched**: `publishing_listing_save`, `publishing_provider_update`, every
  non-publishing table or function, R2 routing (`storage_authorize`), and the migration
  ledger history. The only statement outside `publishing_*` is the bucket insert
  (`on conflict do nothing`).
- **Unique**: no other migration has this version. The R2 migration is `20261107090000`
  in the repo and `20261016113831 storage_r2_routing` in the production ledger, and it is
  independent.

## 4. Rollback (only while no central publication or operation exists)

`docs/publishing/rollback-20261108090000.sql` runs in one transaction. It refuses to run if any
`HOMATCH_ACCOUNT` job or any operation exists. It restores the 8-status CHECK and the two v1
function bodies, drops the new columns, tables, functions and the (empty) bucket, and keeps every
v1 listing and publication. It is proven to restore every fingerprint in
`tests/sql/publishing/rollback.sh`. The engine falls back to v1 mode by itself after a rollback.
